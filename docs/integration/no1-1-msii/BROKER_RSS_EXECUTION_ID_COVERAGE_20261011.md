# MarketSpeed II RSS broker identity coverage (READ ONLY)

Official MarketSpeed II RSS function listing dated 2026-03-30 (user-provided ms2rss_function PDF): RssOrderList can show order number, side and received time; the installed V3 READ ONLY snapshot currently captures only orderNumber, status, symbol, quantity, filledQty. RssExecutionList returns executionDate, symbol, account, market, trade, side, quantity, price, but there is NO unique execution ID and NO parent orderNumber among the official 15 result columns. The present V3 captures nine of these. Thus joining orders to fills based on same symbol/time/quantity is intrinsically ambiguous, especially with personal external holdings or repeated/partial fills. A fabricated ID or a hash of this row is NOT a broker-proven execution identity.

The new broker_identity_coverage module audits legitimate READ ONLY RSS source and frozen Ownership baseline, validates schema/status/date/side/quantity/price and detects personal SELL rows. ALL broker executions remain UNLINKED until a genuine authoritative broker order-execution linkage and unique execution identity is physically established. In particular, personal EXTERNAL SELLs NEVER trigger the Ark No.1.1 first-legal-SELL-fill buy prohibition, and even a SELL row for an Ark-managed symbol cannot be promoted without a verified fill match.

This is not a new manual approval barrier: proper broker ID and order reconciliation is an essential algorithmic condition. Read-only monitoring continues with no orders; integration tests use synthetic account figures and contain no brokerage data. Excel RSS order permission OFF, productionReady false, Frozen/main untouched. Next integration step is a verified broker linkage adapter, not guessing from execution date and symbol.
