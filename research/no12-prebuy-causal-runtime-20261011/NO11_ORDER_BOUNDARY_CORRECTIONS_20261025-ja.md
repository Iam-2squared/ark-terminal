# 既存の注文・取消・注文番号照合：ID範囲と時刻境界の修正

2026-10-25 / 既存PR #592。実口座・発注接続のうち、既存の非送信境界を修正する。新Selector・再学習・Frozen原本・main・別branchの変更はない。

## 修正した実コード

`runtime/synthetic_msii_draft.mjs`、`tools/no11_order_cancel_preview.mjs`、`tools/no11_broker_order_state.mjs`が、共通の`runtime/no11_order_boundary.mjs`を使用する。独立した確認コマンドを追加する変更ではなく、既存の呼出しで適用される。

- BUY/SELLプレビューの発注IDと使用済みIDにも、公式上限2147483647を適用する。従来は正の安全整数なら上限超過でも通っていた。文字列・小数・重複IDは引き続き拒否する。
- 注文プレビューにあった「1秒先までの受信時刻を許容」を除く。判断時点より後の受信は、100nsの差でも拒否する。
- PowerShellの7桁小数秒を100ns精度の整数として保持し、30秒の鮮度境界でも切り捨てない。出力JSONへBigInt自体は含めない。
- 2月29日が存在しない年、4月31日、24:00、無効なタイムゾーンをDate.parseの補正で通さない。JST記録を要求する入口では+09:00を確認する。
- 秒単位のRSS発注時刻は、ローカル記録の同じ秒と比較する。同一秒の末尾`.9999999`を誤って排除せず、1秒前の注文を採用しない。これは精密な実約定時刻の認証ではない。
- 取消時の元注文再構築では、元の観測文字列をそのまま渡す。同じ瞬間の`.0000000`有無を別時刻とせず、元注文の受信時刻を新しい時刻に書き換えない。
