R不明行を0%、MINUS、Cへ補完しない。
将来execution sourceが欠けるという理由で購入前rankから除外しない。
R knownは教師・評価maskであってruntime gateではない。

Downside readoutの4分類target（Rは%単位）:
  T5    : R <= -5
  T3_5  : -5 < R <= -3
  T0_3  : -3 < R < 0
  T_NONNEG : R >= 0

readout出力p5/p35/p03/pnonnegから:
  q5=P(R<=-5)=p5
  q3=P(R<=-3)=p5+p35
  qNEG=P(R<0)=p5+p35+p03
  P(-5<R<=-3)=q3-q5
と計算する。4-class softmaxなので0<=q5<=q3<=qNEG<=1を構造的に満たす。

この4分類は損失側readout用であり、最終評価は必ず指定の1%刻み全12帯。
細帯確率を学習していないのに、-4〜-3%等の予測確率を捏造しない。
それらは今回の観測n/Nとして出す。

======================================================================
7. 有限な損失readout仕様：旧モデルは固定、追加fitを明示
======================================================================

モデル族: 4クラス・L2正則化multinomial logistic readout 1種類。
R1入力: 保存ML、m2、m3、m5。
R2入力: 同じ4列 + 適格と固定したHL0/D1/D2 raw score（最大3列）。
symbol、日付ID、未来のWinner bucket、実現R、EXIT時刻、真のMAE等は入力にしない。

R1/R2とも同じ行集合・targetを使う。
正常数値missingnessは過去学習側の中央値とmissing indicatorを用いる。
model自体の未対応・late input・依存不明は単なる数値missingnessと違う。
その候補には新rankを付けずNATIVE_FALLBACK_UNASSESSEDを付ける。
必要scoreの全欠測を0-riskとしない。

定式化:
  softmax各logit=intercept + beta * z
  objective=平均multiclass log loss + (0.01/2) * sum(beta^2)
  interceptは正則化しない。sample/class weightなし。
  zの中央値補完・平均/標準偏差は当該過去学習集合のみ。
  zero stdは1。raw scoreの向きは元contractどおり保持。
  初期係数0、L-BFGS、gradient infinity norm<=1e-7、最大500iterations。
  0.01や500は今回の固定実装選択であり、過去に最適だった値とは主張しない。
  hyperparameter sweep、early stoppingによる現在block利用、class balancing、SMOTEなし。
  solver/objectiveの正規化がlibraryのC定義と違う場合は上記objectiveへ正確に合わせる。

最大8block × R1/R2各1fit = 最大16個の新readout fit。
ただし最初から全8blockにfitできるとは限らない。

ブロックbの学習集合P_b:
  bより前の許可済みDevelopmentで、原base modelから初回out-of-prefix予測が出ており、
  新EXITのラベルが当時のb開始前に満期・利用可能だった一意Entryだけ。
  現在b・後続b、raw教師未成熟行、元base学習内のin-sample予測は使わない。
  元base train / scaler / encoder依存もbのfutureを含まないことを監査する。
  旧baseを全期間でrefitしたscoreやtraining resubstitutionは、OOFの代わりにならない。

最低学習supportを事前固定:
  P_bのR既知100件以上、10sessions以上、上記4class各5件以上。
  この数字は小標本時のfit棄権条件であり、将来性能の保証ではない。
  不足blockはREADOUT_OFF_SUPPORT。現行rankを残し、未評価fallbackと明示する。
  最初のblockに過去OOFがなければOFFが正しい。warmupをin-sampleで埋めない。

各bで:
  1) P_bと入力DAGのID/hashを固定。
  2) R1/R2をfit、モデル・preprocessing・sourceを保存。
  3) 次節のrisk capをP_bだけで固定。
  4) 現在bを予測し、全raw score/q/rank/reasonをseal。
  5) evaluatorだけが現在bのR/Uへjoinして表を計算。
  6) 同じbの結果を使ってmodel/capを作り直さない。

原本ファイルに未来labelが同居していてもruntime/fit viewへ渡さない。
今回全体が既にDevelopment露出済みであることも別に開示する。
新precommitは過去の研究者exposureを消さない。

8. 新S/A/B/Cの具体的な作り方
======================================================================

上方向gradeは現行のまま保持する。
今回のR1/R2は「上方向要件 AND 大Loser risk要件」の2軸gradeとする。
1本のwinner-minus-loss scoreへ無理に潰さない。

数値risk上限をこの9窓・今の全評価Rから最適化しない。
初回の相対的な上限は、その時点までの元rankの実測riskを基準にする。
ユーザー未指定の『Sは絶対に損失3%以下の確率』等を勝手な保証へしない。

各b、P_b上で元rank累積集合を作る:
  G_S   = old rank S
  G_SA  = old rank SまたはA
  G_SAB = old rank S/A/B

k=3,5について、各集合の既知NとR<=-kのLを数え、
  base_risk=(L+0.5)/(N+1)
を保存する。0件観測を真のrisk0にしないための固定平滑化であり、信頼上限ではない。

capを次で固定する:
  cap_B,k = base_risk(G_SAB,k)
  cap_A,k = min(base_risk(G_SA,k), cap_B,k)
  cap_S,k = min(base_risk(G_S,k), cap_A,k)

これでSのrisk上限<=Aのrisk上限<=Bのrisk上限。
q5<=q3と各capの対応も検査する。
S/A/Bの上限値はblockごとに具体的な%でCAP_SNAPSHOTへ出し、根拠のN/Lも付ける。
capは最大risk予算の研究用参照であり、未来でその率以内になる保証ではない。

最低cap support:
  G_S、G_SA、G_SABそれぞれR既知30件以上かつ5sessions以上。
  どれか不足ならそのbの新grade変更はOFF_CAP_SUPPORTとし、原rankを残す。
  capを大きくして作動を無理に増やさない。

新grade関数（R1/R2共通）:
  - old rank=C: Cのまま。低riskだけで上昇根拠の薄いCをSへ昇格させない。
  - old rank=S かつ q5<=cap_S,5 AND q3<=cap_S,3: S
  - old rank∈{S,A} かつ q5<=cap_A,5 AND q3<=cap_A,3: A
  - old rank∈{S,A,B} かつ q5<=cap_B,5 AND q3<=cap_B,3: B
  - それ以外: C_RISK_DOWNGRADED（表示rankはC、理由は別列）
  - readout/support/as-of不明: 元rank+NATIVE_FALLBACK_UNASSESSED

境界は<=。epsilonを結果に合わせて足さない。
qNEGは全マイナスriskの診断として必ず出すが、初回のhard rank条件には足さない。
小さな負け全体の除去に引きずられ、大Winnerを落とす旧失敗を繰り返さないため、
初回のgrade変更はq3/q5の大Loser2条件に限定する。

同一新grade内は元candidate_orderを維持する。
R2の完全順序は新grade S>A>B>C、その中では元(-ML,-m5,-m3,-m2,時刻,symbol)順。
元順で同点が残る場合だけ既存の完全IDを決定論的な最後のキーにする。
予測riskだけで元上方向の内部順位を追加で並べ替える第二仕様を作らない。

B全体の一律拒否ではない。低riskのBはBのまま、高riskの旧S/Aも降格対象になる。
新rank=Cは今回の診断上の降格であって、Capitalへの実veto実装ではない。

9. 最重要評価：新旧rankごとの全12帯 n/N
======================================================================

評価Rは全て新SHARP_DROP EXIT基準のR_NEW_PCT。
R0だけ旧EXITのR、R2だけ新EXITのRで比較することは禁止。
旧EXITのR_CONTROL表を併記する場合は完全に別の補助表へ置く。

上からユーザー指定順に排他的bucketを固定する。

  P5_PLUS   R >= +5%
  P4_5      +4% <= R < +5%
  P3_4      +3% <= R < +4%
  P2_3      +2% <= R < +3%
  P1_2      +1% <= R < +2%
  P0_1       0% < R < +1%
  L0_1      -1% < R < 0%
  L1_2      -2% < R <= -1%
  L2_3      -3% < R <= -2%
  L3_4      -4% < R <= -3%
  L4_5      -5% < R <= -4%
  L5_PLUS   R <= -5%

ZERO (R=0ちょうど)とR_UNKNOWNは別行。ZEROを小Winnerにしない。
12帯+ZEROの合計が各rankのR既知N、さらにR_UNKNOWNを足すと各rank全N。
符号も既知/不明も混ぜない。

主表のセル:
  n_{rank,bucket} / N_{rank,R_known} (xx.xx%)
例として実測で7件/50件なら『7/50（14.00%）』。
この例は出力形式の説明だけで、Arkの計測値ではない。

必須表A: 全Entry / R0
  行=上記12帯・ZERO・R_UNKNOWN・ALL_MINUS・ALL_PLUS・TOTAL
  列=現行S / 現行A / 現行B / 現行C / RANK_UNAVAILABLE / 全体

必須表B: 同じ全Entry / R1
  同じ行・列順。

必須表C: 同じ全Entry / R2
  同じ行・列順。

必須表D: rankごとの横並び
  『S: 現行 / R1 / R2』『A: 現行 / R1 / R2』等を全4rankで表示。
  各R帯の件数、n/N、率差ppを同時表示する。
  読者が元表を引き算しなくても、上位のLoser/Winnerの変化が分かるようにする。

各表の上に必ず以下を付ける:
  対象全N、rank有効N、R既知N、R未知N、U label既知N、sessions、unique symbols。
  各rank全N、R既知N、R既知coverage、active risk判定N、fallback N。

R_UNKNOWNだけは『unknown N / rank全N』を分母付きで表示。
ZERO・実率のN=0はN/A。0%と表示して安全群に見せない。
旧新rankでR knownの数が変わるのはrank構成の違い。
同じIDのR known/unknownをrank方式で変えてはいけない。

参考として全N分母のbucket率も別列へ出す。
未知があるrankの観測率を全rankの真のriskと断定せず、
各対象bucketについて最小n/N_all、最大(n+N_unknown)/N_allの欠測範囲も併記する。
これは統計的信頼区間ではなく、未知を全て非該当/該当とした範囲である。

保存CSVはlong形式とし、最低列:
  cohort, method, fold, rank, bucket, bucket_n, rank_all_n, rank_r_known_n,
  rank_r_unknown_n, numerator, denominator, fraction_text, rate,
  risk_active_n, risk_fallback_n, session_n, symbol_n, r_namespace

10. ランクを小さくしただけの見かけの改善を防ぐ
======================================================================

『新Sは10件しかないがLoser0件』『旧Sは100件だった』だけでは成功にしない。
以下を主表と同時に出す。

(1) 捕捉率
  n_{rank,bucket} / N_{cohort,bucket}
  例: 全>=5% Winnerのうち何件をS、S+A、S+A+Bに残したか。
  rank内濃度とは別分母であることを列名に明示する。

(2) 累積上位rank
  S / S+A / S+A+Bそれぞれに対し、
  R<0、R<=-1/-2/-3/-4/-5、R>0、R>=+1/+2/+3/+4/+5をn/Nで表示。
  件数、正R mass、負R絶対mass、平均R、中央値Rを併記。
  massは等重みpp-sumで、口座円利益・Capital改善ではない。

(3) 上方向保全
  既存U2/U3/U5/U10、原High帯3〜5%などのn/N・captureをR0/R1/R2で比較。
  U5/U10は実現Winnerと同義ではないので別表。
  R>=+5%だけ残ってもU5/U10が大きく消えている設計を無条件に成功としない。

(4) 移動表
  old S/A/B/C → new S/A/B/Cの4×4をR1/R2とも作る。
  各cellの全N・全12帯・U5/U10・正負massを保存。
  q3/q5のどちらで降格したか、双方か、fallbackかを保存。
  旧B→Cに落とした大Winnerも必ず表示する。

(5) 同数予算の順位比較（評価専用）
  全方法のrisk出力とrankをsealした後、各評価block内の同じ候補集合で実施。
  Kは元R0のS件数、S+A件数、S+A+B件数の3つに限定。
  KはR未知を除く前の件数から決め、R1/R2も同じKだけrank順に取る。
  選択後にR既知/未知を分け、全12帯・U capture・massを比較する。
  新rankの人数縮小だけの効果と、順位自体の追加価値を分ける。
  このwhole-block top-Kは事後のランキング診断であり、未来の候補全数を
  当日の購入判断に使う新policyではない。runtime閾値へ輸入しない。

(6) 分割・依存性
  全8block・全session、元rank×risk分位、early/late時刻帯は固定区分で補助表示。
  active subsetとfallback-inclusive全体を両方出し、都合よい方へPrimaryを替えない。
  session一つずつ除外した同一固定rankの再集計で集中度を示す。モデル再fitなし。
  pooled OOFも独立した未使用OOSではない。小さな帯の率だけで一般化しない。
