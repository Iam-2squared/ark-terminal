  第1層 FIRST LAYER       : 現行状態を固定。
  第2層 上方向H2/H3/H5・ML : 固定。Entry→Highの思想を変更しない。
  第2層 下方向予測器       : このWorkで新規研究する。

  新SHARP_DROP EXIT        : 固定。旧EXITへ戻さない。

大Loser濃縮・Winner巻込み・U2/U3/U5/U10保全を必ず出す。
「今のSの中の危険なものを見分けられるか」を直接確認する。

3. 学習・評価母集団とラベル
======================================================================

3.1 固定単位
  一意Frozen Entry IDが1サンプル。symbol-dateへ縮約しない。
  RESET20の重複898取引などを独立サンプルとして増やさない。
  CORE1600 / warmup20 sessions / 評価38 sessions・1039 ID / 既存8blockを継承する。
  session全件がtrainか評価側のどちらかへ属する。行単位random splitは禁止。

3.2 Primaryラベル
  R_NEW_PCT = 100 * (sell_credit_new / buy_debit_frozen - 1)
  新SHARP_DROP EXIT、元buy fill、既存cost、100株を固定。
  分子/分母または保存Decimal原値を権威とし、表示丸め前に分類する。
  RはEntry→EXIT実現net return。MAE、Entry→Low、Entry→Highとは別。
  損切りtriggerの時刻・EXIT reason・future pathはラベル計算側にのみ置く。

3.3 新モデルが直接学ぶ5分類（排他的）
  T5       : R_NEW_PCT <= -5
  T3_5     : -5 < R_NEW_PCT <= -3
  T2_3     : -3 < R_NEW_PCT <= -2
  T0_2     : -2 < R_NEW_PCT < 0
  NONNEG   : R_NEW_PCT >= 0

  出力p[0..4]から以下を算出する。
    q5   = p(T5)
    q3   = p(T5) + p(T3_5)
    q2   = p(T5) + p(T3_5) + p(T2_3)
    qNEG = p(T5) + p(T3_5) + p(T2_3) + p(T0_2)
  よって0<=q5<=q3<=q2<=qNEG<=1をモデル構造で満たす。
  -5〜-3%の推定はq3-q5。細かい1%刻み12帯は観測評価であり、
  12クラスそれぞれを予測していると主張しない。
  q3を主識別対象、q5を必須の重大損失対象、q2/qNEGを補助とする。
  q5の小標本を隠さず、q3だけの改善を「-5%も解決」としない。

3.4 ラベル再利用と欠損
  RD01の1039 IDは保存R_NEWを再利用。既知1016の再生成0。
  元23未知はUNKNOWNのまま。未来の価格sourceがないことを購入前gateにしない。
  warmupは元561行を想定するが、原台帳を権威とする。
  旧EXITのwarmup Rを新EXITのRとして使わない。
  warmupに同一新EXIT Rが未保存なら、そのIDだけ最大561件、各1回、
  保存market/State/修復済みEXITから新namespaceへmaterializeすることを許可する。
  既存ラベルはhash一致を確認して再利用。生成attempt数/成功/未知を別カウント。
  必須suffixが欠けたwarmupはラベルUNKNOWN。回復のためprovider/RAW recoveryをしない。
  不足しても利用可能な過去行で定義済みsupport条件を評価し、勝手な追加期間を足さない。

3.5 時系列成熟
  block bのfitへ渡すのは、b開始前の凍結train sessionsに属し、
  ラベル確定可能時刻もbの学習cutoffより前であるIDのみ。

5. 入力representation：少数family・事前固定のshape
======================================================================

今回は以下のF_PRICEとF_STATEだけ。
新しく学習した上方向score・旧Downside score・銘柄ID・日付ID・fold IDを入力にしない。
peer/market指数、新しい日足期間、news、板、deep modelを後付けしない。

5.1 共通のデータ処理
  既存P0 snapshotはexact row IDでjoinし、列の計算定義・cutoffが以下と一致する場合だけreuse。
  近い名前の列を意味が同じと推定しない。
  不一致なら、既存raw prefixの限定sliceからこのWorkの新featureとして算出する。
  全featureはformula、source member/hash、available_at、missing reasonを保存。

  窓は同一session内の直近5/20/60 active minutes。
  凍結calendarの予定regular分足区間で選び、昼休みの非取引分を足さない。
  予定欠測を「最後の60本」で埋めず、coverageを下げる。
  朝以前の前日バーへ延ばさない。過去sessionへの勝手なcarryをしない。
  reset/gap/lunchにより断絶する隣接リターンを作らない。
  窓内の最大/最小など集合統計は利用可能な実観測のみ、連続性統計はsegment内のみ。

5.2 F_PRICE（価格・チャート形状・Volume・Trading Value）
  各w=5/20/60で次の12数値。計36列。
  a) valid raw数 / 当session内その窓の予定raw数（coverage）
  b) log(最後のC / 最初のO)：窓内値動き。gapを含む集合統計として明示。
  c) log(max H / min L)：窓レンジ
  d) log(最後のC / max H)：窓高値からの位置
  e) log(最後のC / min L)：窓安値からの位置
  f) Σ隣接log return / Σ|隣接log return|：符号付き効率
  g) sqrt(mean(隣接log return^2))：リターンRMS
  h) segment内close-to-running-close-highの最悪log drawdown
  i) 有効隣接pair中、close return<0の割合
  j) 隣接close下落barのVolume合計 / 有効隣接barのVolume合計
  k) log(1+窓内1観測bar当たり平均Volume)
  l) log(1+窓内1観測bar当たり平均Trading Value)

  注意:
  ・hはClose系列だけを用い、同一足High→Lowの順序を推定しない。
  ・fでpairがあり絶対変化合計0なら0、pairなしならmissing。
  ・hで長さ>=2のsegmentがなければmissing。値動きが無ければ0。
  ・jは約定方向の実買い/実売りフローではなく、OHLCVの代理統計。
  ・k/lのraw単位をpinする。単位換算を結果で変えない。
  ・missing/NaNを0埋めして下落なしとしない。

  上記に以下9数値を追加。F_PRICEは合計45数値を固定。
  m) 最後の足のbody=(C-O)/(H-L)
  n) 最後の足のupper_wick=(H-max(O,C))/(H-L)
  o) 最後の足のlower_wick=(min(O,C)-L)/(H-L)
  p) 最後の足がflat OHLCであるindicator（flat時m/n/o=0、欠測時missing）
  q) log(平均Volume5 / 平均Volume20)
  r) log(平均TradingValue5 / 平均TradingValue20)
  s) 当sessionのregular開始からt_xまでの予定active minute数
  t) 最後のvalid raw closeからt_xまでの予定active minute age
  u) 直近60 active minutes内の凍結raw segment断絶数

  比率q/rは分子分母のsourceがvalidかつ正のときだけ定義。
  足不足/分母0へ恣意的epsilonを足して値を捏造しない。
  tはageがあることを可観測にするだけで、stale Stateの持ち越しを許可しない。

5.3 F_STATE（State9・Transition・Pathの保存prefix）
  kernelを再計算しない。BUY_INTENT cutoffで合法な保存prefixだけを切り出す。
  既に契約上失効した最後のStateを「現在State」として持ち越さない。

  4 categorical:
    ・cutoff時点のprimary State9またはINITIALIZING/QUALITY_ABSTAIN等の品質値
    ・同一有効segment内、直近State runの1つ前のState
    ・同じく2つ前のState
    ・凍結quality/reset reason
  StateにRISEからSHARP_DROPまで大小の整数順序を付けず、固定語彙one-hot。
  State語彙は9State＋明示品質語彙＋START/UNKNOWN。
  固定語彙・列順をfit前にmetadataから確定し、将来の頻度でcategoryを統合しない。

  直近20/60 active minutesで各11数値。計22列。
    ・9State各々の観測checkpoint占有率（有効State観測数が分母）
    ・有効State観測checkpoint数 / 予定checkpoint数
    ・同一有効segment内のState変化回数
  有効観測0なら9占有率はmissing、coverageは0。
  同一runの繰返しStateを新transitionと数えない。
  昼休み/品質断絶を市場のDROP/RANGE transitionへ数えない。
  segment終端やreset reasonを、t_x後のsuffixから遡って補完しない。

  さらに3数値:
    ・現在の有効State runのactive-minute duration
    ・最後の有効State checkpointのactive-minute age
    ・直近60 active minutesのState reset/segment断絶数
  合計25数値＋4categoricalを固定。

5.4 INPUT品質とfeature missing
  raw/Stateの真の欠測・INITIALIZINGは、凍結missingnessとして学習に表現する。
  「保存すべきprefixファイルがない」というEVIDENCE_GAPとは分ける。
  F_PRICEに最後の合法valid raw barが無い場合、新モデルの数値予測はUNASSESSED。
  Stateが正当にINITIALIZINGでもF_PRICEが有効ならcombined modelは予測可能。
  State記録の保存欠落はcombined系だけUNASSESSED。price-onlyを黙って代入しない。
  family全体が未回収ならMODEL_NOT_RUN_SOURCE_BLOCKEDとし、別featureへ置換しない。

6. モデル：3構成だけ、Primaryは先に固定
======================================================================

名前                  入力              学習器                  役割
D-LINEAR              PRICE+STATE       L2多項logistic          低容量・線形対照
D-PRICE               PRICE             浅い勾配boosting木      価格/需給だけの対照
D-FULL                PRICE+STATE       同じ浅いboosting木      事前固定Primary

旧HL0/D1/D2/RD01の出力は新入力に足さない。deep learning・別アルゴリズム追加なし。
3構成は同じtrain IDとtargetで比較し、MODEL SOURCE欠損時のmask差を明示する。
Primaryを結果を見てD-PRICE/D-LINEARへ付け替えない。
対照が良ければ次工程の候補として報告するが、このcycleで新Championにしない。

6.1 前処理
  数値70列（PRICE45＋STATE25）はtrain内の中央値で補完。
  全数値列にmissing indicatorを付ける。train全欠測列の中央値は0として記録。
  D-LINEARはtrain mean/stdで標準化。std=0はscale=1。
  木は同じ補完/indicator、標準化なし。
  固定one-hot categoryを使用し、unseenはUNKNOWN。
  新TESTの分布で補完/標準化/カテゴリ統合しない。
  winsorization、PCA、feature選別、SHAPに基づく再選択は0。

6.2 D-LINEAR
  class order=[T5,T3_5,T2_3,T0_2,NONNEG]
  objective = mean multiclass negative log likelihood + 0.005 * Σβ^2
  intercept非正則化。係数全0初期、基準class=NONNEG（β/intercept=0）で一意化。
  L-BFGS、float64、最大1000 iterations、gradient infinity norm<=1e-7。
  未収束を成功にしない。iterationを追加して救済することはこのcycleではしない。
  表記上L2=0.01/2に相当。実装APIのC値と同値と推測せず目的関数を合わせる。

6.3 D-PRICE / D-FULL
  HistGradientBoostingClassifier互換のmulticlass log_loss。
  learning_rate=0.05、max_iter=100、max_depth=3、max_leaf_nodes=7、
  min_samples_leaf=20、l2_regularization=1.0、max_bins=64。
  class_weight=None、sample_weight=None、early_stopping=False、warm_start=False、
  random_state=57、categorical_features=None（one-hot済み）、monotonic_cst=None。
  feature subsamplingは行わない（max_featuresを持つ版では1.0）。
  行subsampling・balanced weight・SMOTE・oversampling・cost-weighted label変更なし。
  random validation split、評価blockを渡したearly stoppingを禁止。
  100 roundsは固定値であり、q5成績を見て増減しない。
  多クラスのため1round=最大5本の木。1fitを「1本の木」と呼ばない。

  library / Python / NumPy / SciPy / sklearn version、threads、dtype、model形式をpin。
  保存済み環境を優先し、動作する互換版を1つだけ事前固定。結果のためのversion探索なし。
  入力数値・logistic・boostingの解釈が異なる場合はfit前に契約不一致として記録。

6.4 非学習baseline
  B0: 同じtrain labelのclass頻度をDirichlet0.5で平滑化。
      p_k=(n_k+0.5)/(n_train+2.5)。現在blockの頻度は使わない。
  定数baselineなのでblock内AUCは0.5（片classならN/A）。pooledはblock差を持ち得る。
  B0は新予測器の有効coverageとして数えない。

6.5 出力の呼称
  qは推定riskであり、測っただけで校正済み損失確率とは認定しない。
  今回calibration fitは0。確率の検証を通過するまで「-5%になる確率が保証○%以下」なし。
  標準化/補完のfitは各model fitと別にカウントする。

7. 時系列OOFと有限予算
======================================================================

既存8つのrolling-origin train/evaluation sessionをそのまま使用する。
各blockの元trainにはwarmup20 sessionsと、その時点までの過去評価sessionsが含まれる。
評価38sessions全1039 IDは、利用可能入力に対して各methodで初回OOFを1回出す。
train/testという旧ファイル名だけでProtected TESTへアクセスしてよいと解釈しない。
今回許可は既存Development台帳の58sessionsのみ。

各block bの手順:
  1) train ID、時刻、sourceを固定して、過去の既知R_NEWだけを渡す。
  2) 前処理とmodelをfit。必要原本をpublic/privateへ保存。
  3) 評価blockのfeatureのみを予測workerへ渡す。
  4) q、asof、coverage、model hash、row orderをseal・保存。
  5) seal後に当blockのR/U/元R0等を評価workerへjoinする。
  6) blockを保存して次へ進む。成績によるhyperparameter変更はしない。

前処理/model fitの最低support（性能Gateではなく実装事前条件）:
  train R既知>=200、train sessions>=10、5クラス各>=3。
  不足blockはOFF_SUPPORT。新qはnull、参考B0を別列に表示。
  判定対象を後のblockだけへすり替えず、全1039のOFF割合を残す。
  support3で校正が十分とは主張しない。陽性の少なさは別にLOW_SUPPORT表示する。

上限:
  新base model fit: 3構成×8block=最大24（新ターゲット5分類のfit）。
  新calibration fit: 0。
  旧base refit / 旧score再推論: 0。
  新S/A/B/C policy生成: 0。
  runtime threshold探索 / 新veto / Capital Replay: 0。
  既知1039 R_NEWの再生成: 0。
  未保存warmupラベルの限定materialization: 最大561 ID、各1回。
  新feature campaign: 1つの固定仕様、最大1600 ID。完了IDは再利用。

技術修復は最大20cycle。過去cycleの修復数とは別に台帳管理する。
修復でfeature意味、target、split、モデル設定を変えない。
fit中断後の同設定再attemptは全model横断で最大4回、24成功fitとは別カウント。
同一outcomeを見た完了fitのやり直しや別seed試行は不可。
原ファイル不在なら所在探索を同じ箇所でループせず、不足exact memberを記録する。

======================================================================
10. 損失濃縮とWinner保護を同時に測る
======================================================================

全て同じraw ID maskと既知labelで計算する。
  Tail recall: FLAGされたR<=-3/-5件数 / 全該当件数。
  Tail precision: FLAGされた該当件数 / FLAG内R既知件数。
  Tail enrichment: precision / 全体同target率。
  Winner damage: FLAG内R>=+2/+3/+4/+5件数 / 全該当Winner数。
  U damage: FLAG内U2/U3/U5/U10件数 / 全該当U数。
  未FLAG側のWinner/U captureとdensityを双方表示する。

無情報対照はblock内で同じkを選んだときの解析的期待件数。
例えばblockのtarget既知N_b中positive T_b、FLAG内既知k_bなら期待k_b*T_b/N_b。
R未知を含む実選択では、既知mask条件付きの期待であることを記載。
「無作為よりtailが多い」だけでWinner保護まで成立としない。

正mass=sum(max(R,0))、負abs mass=sum(max(-R,0))を別々に保存。
FLAGで失う正massと、FLAGにある負abs massを並べる。
これは等重みpp-sum。円損益・回避損失・Final Equityではない。
U5/U10と実現Loserは重なり得る。互いに排他的な正負クラスにしない。

全体、各block、各session、元rank、実行適格集合、元R0通過集合を表示する。
E0の既存funded集合は追加の条件付き診断のみ。
fundedされていないEntryを学習から落としたり、未来のE_ONLYへ絞ったりしない。

18. Workへの開始文
======================================================================

RD01の完了地点を引き継ぎ、このRD02だけを実行してください。
上方向H2/H3/H5、R0、FIRST LAYER、V5、SHARP_DROP EXITは固定です。

今回は旧scoreの小さなreadoutではなく、BUY_INTENTまでに合法な価格・Volume・
Trading Value・State prefixから5クラスの損失severityを直接学習します。
D-LINEAR / D-PRICE / D-FULLの3構成・最大24fitだけを、既存8blockで比較してください。
新rank capやCapitalを先に触らず、大Loserの識別とWinner保全を全12帯n/Nで確認してください。

工程ごとの確認待ちは挟まず、許可範囲を有限に完走してください。
入力不足時は定義されたUNKNOWN/OFFを保ち、架空の比較や成功判定を作らないでください。
保存済み1039 R_NEW、raw、State、失敗記録を再利用し、warmupで本当に未保存の
新EXIT Rだけを限定作成してください。Phase 0やRAW recoveryへ戻らないでください。

各blockを保存・実読戻しし、独立検算・保存モデル再現・最終保存確認まで完了してください。
その後、性能とcoverageを分けて報告し、Ranking統合は設計提案まででSTOPしてください。
