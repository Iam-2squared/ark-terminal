# Phase57 State v3 — 9-Pattern Price-Shape Contract v1

Status: `STEP1_DEFINITION_FROZEN`; scope: definition and contract verification only.
Start PR #587 HEAD: `ca3e0fe6982d5e8e5b54de551bac5ca4f3e3f009`.
This is an independent Ark intraday adaptation of the nine Japanese chart-shape names, **not** a reproduction of Rakuten Securities' daily-chart classifier or its unpublished thresholds. The official help describes a daily-chart search with nine or 25 patterns: https://marketspeed.jp/ms2/onlinehelp/ohm_006/ohm_006_14.html . All numbers and tie-breaks below are Ark precommitted design choices, not empirically fitted results.

## Scope, output and totality

Layer 1 is price shape only. One valid as-of price anchor yields exactly one `state` from `RISE_STOP, RISE, SHARP_RISE, PULLBACK, RANGE, REBOUND, SHARP_DROP, DROP, DROP_STOP`. There is no `UNKNOWN`/`INVALID` tenth state and no outcome-informed eligibility filter. Output is `{state, dataQuality, confidence, reasonCodes, asOf, lastPriceTime, inputCutoff, contractVersion}`. `state` is nullable **only when** no trustworthy positive price anchor exists (`dataQuality=INVALID`, `stateStatus=NOT_COMPUTED`), or timestamps/price integrity cannot be ordered; such a record is still retained and counted in a separate invalid-data denominator. Never report zero unknown by silently excluding invalid records.

Data quality: `OK` means as-of closed observed anchors, valid prior session if present, no observed integrity conflict, and recent expected active-minute coverage >=80%; `DEGRADED` means usable positive anchor but prior session absent, <80% recent coverage, stale last anchor, missing official open, or a documented corporate-action discontinuity with no PIT-consistent adjustment. `INVALID` means no positive finite trustworthy anchor, conflicting timestamp ordering, or unresolvable adjustment identity. Missing bar is *unobserved*, not inferred no-trade. `confidence` is categorical `HIGH/MEDIUM/LOW/NOT_ASSESSED`: HIGH if quality OK and both direction segments each have >=2 observed transitions; MEDIUM if quality OK with one segment short or quality DEGRADED with both segments represented; LOW for all other classified DEGRADED/short-history cases; NOT_ASSESSED iff INVALID. Confidence never selects or modifies state. `reasonCodes` preserve missingness/staleness/boundary reasons separately.

## Causal inputs, clock and normalization

Allowed: PIT-known previous trading session's observed, timestamped price series and today's official open (only after published), plus completed price bars with `barEnd <= asOf` and publication/ingestion availability `<= asOf`. Use close as the bar point; official open is a distinct time-zero anchor. Previous-session first/last observed anchors provide direction context, not a tradable overnight trajectory. Previous day may be incomplete and is then flagged DEGRADED. Prior to today's first observed price, use last previous-session *known close* as a one-anchor prior context; if not available, INVALID. Never invent an open, zero-volume bar or interpolate missing minute prices. Use an exchange calendar for active-minute arithmetic; 11:30–12:30 recess is not a minute of elapsed active time. Exactly one anchor at NOW is enough for classification but not for a claimed intraday trend. Do not stitch overnight or lunch endpoints into a single-bar return or acceleration. Lunch may preserve the morning directional context but requires a new post-lunch close before claiming afternoon acceleration or reversal. If a completed bar is published after asOf, it is excluded. A stale latest bar may be classified with DEGRADED/LOW; it must not create a synthetic flat plateau.

All calculations are log prices, `log(p2/p1)`, with positive PIT-consistent prices. Define a fixed magnitude unit `U=max(log(1.001), 0.5*median(abs(r_i)))`, where `r_i` are available adjacent, actually observed previous-session *same continuous auction* one-active-minute log returns; use the floor if there are none. No future volatility, all-day current range, future-normalized scale, or cross-sectional fitting. `eps=U`, `shock=3U`, `plateauTolerance=U`. The previous-day U is frozen at the prior close and does not evolve intraday. Overnight gap is recorded as context (`log(todayOpen/priorClose)`) but excluded from both segment slopes, swing magnitudes, U, and shock tests. No pivot may be backdated: a turn first established at t has availability t, even if its price extremum was earlier.

Define current episode points as official today open (if known) plus observed completed closes up to NOW, ordered by availability, duplicate timestamps resolved only by source provenance (unresolvable conflict => INVALID). `R` is the last up-to-10 **active-minute** segment of today's *same continuous auction* containing the latest point and the latest preceding point inside that segment. If fewer than two observed anchors exist in it, set `R` to no-direction (`0`) and flag sparse/stale; **do not** bridge beyond ten active minutes to manufacture a current slope. `E` is today's earlier segment from today's open (or earliest observed close if open missing) to the R boundary; if there is no R preceding point, E extends through the latest point. If E has fewer than two observed transitions or `abs(E return)<U`, use prior-session first-to-last observed return as the prior-direction context if valid, otherwise zero. A previous-day direction is context only: do not add its return to today's return or compare levels across the gap.

`priorDir=sign(E return)` or the context return with threshold U, otherwise 0. `recentDir=sign(R return)` with threshold U, otherwise 0. For the opposing-direction test, `priorMagnitude=abs(E return)` when E determines priorDir, otherwise `abs(previous-session return)`; `recentMagnitude=abs(R return)`. For `priorDir=+1, recentDir=-1`, a genuine *partial* retreat is PULLBACK iff recentMagnitude < priorMagnitude; complete erasure/overshoot is DROP. The exact equality goes to DROP. Symmetric `-1,+1` is REBOUND iff recentMagnitude < priorMagnitude; equality or overshoot goes to RISE. This cross-session comparison uses dimensionless return magnitudes, never a gap-adjusted price level.

Shock eligibility needs `recentDir!=0`, >=3 observed transitions in R, `recentMagnitude>=3U`, `abs(E return)<2U` (if no E, the previous-day direction magnitude <2U), and `recentMagnitude / max(1, R active minutes) >= 2 * abs(E return) / max(1, E active minutes)` (previous-day context uses its own active minutes). Eligible positive/negative shocks are SHARP_RISE/SHARP_DROP, respectively, **only when priorDir=0 or priorDir=recentDir**. Opposing-direction reversals take precedence, so a downtrend's abrupt rebound remains REBOUND/RISE rather than SHARP_RISE. This is a deliberate separation of reversal from acceleration.

Stop eligibility requires `recentDir=0`, >=2 observed transitions in R, a directional prior segment, latest R price within U (log units) of the *observed as-of maximum* (RISE_STOP) or minimum (DROP_STOP) of today's episode, and no missing recent expected active minute. A prior-day-only directional context needs at least two current-day transitions before claiming a stop. Non-extremal flat trading is RANGE. An absent/stale R never proves a stop; carry priorDir as RISE/DROP with LOW confidence instead. For a real oscillatory R whose abs net return <U but high-low >=2U, stop is allowed only at the appropriate edge and with prior direction; otherwise RANGE. As-of extrema use the prefix only, never future session High/Low.

## Exhaustive decision order (normative)

1. Validate admissible anchors and data quality. INVALID returns null state, no tenth label.
2. If R has no two points, classify `RISE`/`DROP` for directional prior context, else `RANGE`. This is evidence preservation, not fake stop/UNKNOWN.
3. If prior and recent oppose: `(+,-)`: PULLBACK if partial, otherwise DROP; `(-,+)`: REBOUND if partial, otherwise RISE. These outrank shock.
4. If recentDir=0: prior positive => RISE_STOP only with stop eligibility else RISE when R has insufficient transitions or RANGE when observed flat away from top; prior negative symmetric DROP_STOP/DROP/RANGE; prior zero => RANGE.
5. If recentDir positive: eligible shock => SHARP_RISE, otherwise RISE. If negative: eligible shock => SHARP_DROP, otherwise DROP. All exact threshold equality counts as directional/shock/stop proximity; opposing magnitude equality counts as full reversal. This order is total for every valid anchor path.

### Nine names and semantic separation

| Stable ID | 日本語 | Human chart meaning | Decisive causal evidence / distinction |
|---|---|---|---|
| RISE_STOP | 上昇ストップ | Previously rising, now observed plateau at the as-of top | prior +; R flat with >=2 transitions and near prefix high; down R becomes PULLBACK/DROP |
| RISE | 上昇 | Current upward direction without eligible acceleration, or carried positive context on short history | recent +; not eligible SHARP_RISE; opposing down context fully erased distinguishes from REBOUND |
| SHARP_RISE | 急上昇 | Flat/gentle direction accelerates sharply upward | positive >=3U, fast and sufficiently observed; reversal context cannot qualify |
| PULLBACK | 調整 | Up move partially retreats, still smaller than prior up leg | prior + and recent -, abs recent < abs prior; full erasure becomes DROP |
| RANGE | もみ合い | Actually directionless/oscillating or one-anchor no directional evidence | neither direction; or observed flat away from earlier directional extremum; not catch-all for missing evidence with prior trend |
| REBOUND | リバウンド | Down move partially reverses upward | prior - and recent +, abs recent < abs prior; full recovery becomes RISE |
| SHARP_DROP | 急落 | Flat/gentle direction accelerates sharply downward | negative <=-3U, fast and sufficiently observed; reversal context cannot qualify |
| DROP | 下落 | Current downward direction without eligible acceleration, or carried negative context on short history | recent -; not eligible SHARP_DROP; prior-up full erasure distinguishes from PULLBACK |
| DROP_STOP | 下げ止まった | Previously falling, now observed plateau at the as-of bottom | prior -; R flat with >=2 transitions near prefix low; up R becomes REBOUND/RISE |

Every pattern uses the same permitted input set, normalization and decision order above. HH/HL/LH/LL and directional swing counts may be emitted later as descriptive prefix-only diagnostics, but are **not** gates in this frozen v1 contract; no unconfirmed pivot backdating or mutable hidden threshold is allowed. Slope is R/E log-return divided by active minutes; acceleration is the fixed shock rule. `range` means observed prefix max-min and never the later session range.

## PIT boundary and future exclusions

No `barEnd>asOf`, late-published bar, future State v2 or future_resolution_v2, Oracle Low/High, future MFE/MAE, path class, future return, outcome, capture, Entry result, dictionary-derived outcome, fitted test-population scale, future-confirmed pivot, or post-asOf corporate action. Previous session must be identified from exchange calendar as of decision; vendor historical correction must have PIT version available as of NOW or be rejected/flagged, never silently substituted. Never filter opportunities based on outcomes or invalid quality; carry null-state invalid records in accounting. State v2 is historical diagnostic/reference only and is not mapped into this new vocabulary.

Volume is reserved as independent Layer 2 annotation. It is not an input to Layer 1, cannot alter the nine IDs, and is not implemented in STEP 1. No State v3 classifier or 2,155-Opportunity replay is implemented here.
