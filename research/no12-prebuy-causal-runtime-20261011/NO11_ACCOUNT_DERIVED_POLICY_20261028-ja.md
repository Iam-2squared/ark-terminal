# 2026-10-29 最新確定：Ark の運用資金は楽天証券口座内の現金のみ

> 2026-10-29 のユーザー明示指定：「マネーブリッジはしない。口座内にある金だけで」。本書は 2026-10-28 の「口座連動の全額配分」方針を**証券口座内現金限定**に具体化し、以前の「100万円固定」案より優先する。方針変更は**実注文許可ではない**。

## 運用資金の厳格な範囲

- Ark が使用してよい資金は、**楽天証券の証券口座内に現に存在し、その時点で利用可能と確認された現金のみ**。楽天銀行その他銀行の残高、マネーブリッジ／自動入出金（スイープ）によって将来補える資金、未入金の予定額は **一切対象外**。
- Ark は銀行口座との資金移動や自動入金を実行しない。証券会社側の自動スイープが設定されていても、Ark の資金算定では銀行残高を除外する。証券口座内の現金と銀行連携分を確実に区別できない場合は、新規 BUY を停止し、推定値や手入力した根拠のない金額で補わない。
- **RssCapacityList の「現物買付可能額」＝証券口座内の預り現金**とはみなさない。銀行連携分を含むことがあるため、当日の証券口座内現金の内訳・確認時刻・残る注文/資金拘束・費用を実証して照合する。RSS買付可能額は追加の上限制約として使えるが、単独では Ark 配分資金の根拠にならない。
- 配分候補の上限は、**実証した証券口座内使用可能現金**を超えないこと。未約定注文の資金予約、実約定代金、手数料・税等を反映し、二重計上を防ぐ。予想残高・仮の100万円・未確認の銀行残高で補填しない。
- 初日から確認済みの証券口座内運用可能現金全体を元 Capital V5 の**判断対象**にする。少額から増やす暫定運用プランは採用しない。ただし全額を即日 BUY する指示ではなく、元の配分、MAX3、100株単位、時刻、現物 LONG 等の判断を変えない。

## 保有・商品・売却権限の保護

- **現物株の買いのみ。信用取引、信用返済、空売り、レバレッジは一切禁止**。
- Ark 以前の既存保有と、ユーザーの手動注文・手動買付は **EXTERNAL**。Ark は勝手に売却しない。Ark の正規注文ID・約定・数量・所有権が照合できた **ARK_MANAGED** 部分だけを既存 EXIT の対象とする。
- Ark が持つ銘柄をユーザーが手動で買い増した場合も、合算数量を Ark の売却数量とみなさない。区別できないときは新規自動売却を保留して照合する。Ark 管理分のみ MAX3 とする。
- 既存 Frozen Selector / State9 / P1 F5 / H235 / Capital V5 / Structural EXIT の重み・ルールと原本は変更しない。

## LIVE 移行までの最小必須条件

1. 当日の正式入力（G1、Chart50、前日分足、企業行動・価格基準）と Frozen 判断・EXIT の実データ Preflight。
2. 現物の実口座RSS読取・保有／注文／約定／発注ID照合と **証券口座内使用可能現金の独立した検証**。銀行分を混入させない予算上限と、注文・約定後の残高更新。
3. 物理Excel/MarketSpeed IIで送信不可（トリガー0）・送信境界・再送禁止・部分約定・取消・実保有EXIT・通信断/緊急停止を最低限検証。安全条件が揃った日に限り本人が実注文を明示許可する。長期間のShadow成績待ち、再学習、UI意匠調整は先行条件にしない。

## 実装状態との区別

2026-10-29 の実機RSS口座観測では注文・約定・保有・現物買付可能額の**読取と一致確認**は PASS。しかし、証券口座内の現金と銀行連携分の内訳は未認証。既存 Broker Ledger は `allocatedCashJpy` を設定から初期化し、実証済みの証券口座内現金を直接入力する本番接続が未完成。**本書は仕様を確定するもので、コードの資金上限ゲートや実送信/EXITを認証したものではない。**

この仕様の実装・実機検証が済むまで `productionReady=false` / `orderTransmission=false` を維持し、未確認資金を使った注文は許可しない。口座残高・注文番号・個人保有など非公開データは GitHub に保存しない。
