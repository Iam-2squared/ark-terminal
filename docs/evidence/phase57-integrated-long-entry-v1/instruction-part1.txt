■ 今回のEntry Architecture
==================================================

単一の単純BUY/SKIPだけではなく、

Multi-Route Integrated Entry

として事前設計する。

概念構造:

Opportunity
        ↓
Integrated PIT Context
        ↓
┌─────────────────────────────┐
│ Route A: Immediate Entry    │
│ Route B: Pullback Entry     │
│ Route C: Short WAIT         │
│ Route D: Skip / Expire      │
└─────────────────────────────┘
        ↓
Actual Entry

==================================================
■ Route A — Immediate Entry
==================================================

目的:

Opportunity発生直後から伸びる

IMMEDIATE_WINNER
FAST_WINNER

をWAITで逃さない。

Selector / momentum / relative strength /
market context / volatility / price state等から、

Immediate Entry価値が高い場合は
BUY_NOWを許可。

future winner labelをruntime featureにしない。

==================================================
■ Route B — Pullback Entry
==================================================

目的:

Opportunity発生後に一度逆行するが
その後上昇するOpportunityを、

Immediateより良いLocationでEntryする。

v3で確認した

Pullback
Stabilization
Reclaim
Reversal

等のstateをContextと組み合わせる。

重要:

Pullback単体をBUY signalにしない。

v3ではPullbackが
Continued Failure側にも非常に多かったため、

Pullback
+
Comprehensive PIT Context

として評価する。

==================================================
■ Route C — Short WAIT
==================================================

BUY_NOWには弱いが
SKIPするほどOpportunityが壊れていない場合、

短時間WAITを許可。

v1のような長時間WAIT / EXPIRE biasは禁止。

v2のようにWAIT=0になる構造も避ける。

WAIT semantics / max durationは
TRAIN測定前に固定。

結果を見て変更しない。
