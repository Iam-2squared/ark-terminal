# Ark Terminal 統合 No.1.1 — 実売買の許可は1つだけ
更新: 2026-10-10 JST
状態: **ユーザー指定の実装方針 / LIVE実装・実機認証は未完了**

## ユーザーが手動で切り替える許可は1つ
- **MarketSpeed II RSS のExcel側注文機能の利用許可（ON/OFF）だけ**をユーザーの手動発注許可とする。
- Ark Terminalの「実売買を許可」「本番昇格」「Kill Switch解除」「独立監査承認」「マイクロライブ承認」など、重複する**ユーザー操作の許可スイッチ**は設けない。
- Excel側の注文許可OFFなら送信しない。ONであっても、戦略がBUY/SELLを出さない限り注文しない。
- Excel側の設定・注文RSSの振る舞いは本番接続時に公式仕様とWindows実機で確認する。Excelの設定のみで安全が完全保証されるとはみなさない。

## 手動許可と別物の自動検証（維持）
これらは「もう1つのロックをユーザーが解除する操作」ではなく、注文ごとの機械的な成立条件。
- Frozen統合 No.1.1のBUY/SELLだけを使う。Selector / Entry / EXIT / Capitalを変更しない。
- 日本株現物LONGのみ、100株単位、MAX3、資金不足なら発注しない。レバレッジ・信用・ショートへ切り替えない。
- 真の保有・現金・注文・約定・銘柄ID・元データの時刻を照合し、二重発注・誤発注を防ぐ。
- **当日最初の合法なSELL約定後は新規BUY禁止**というFrozen戦略ルールは絶対に残す。これはユーザー向け許可ロックではない。
- 失敗・データ欠落・不整合があれば、その注文を自動で停止する。独立した「解除承認」クリックは原則要求せず、検証可能な復旧を実装する。検証できない不整合を勝手に成功へ読み替えない。

## 工程をシンプルに
1. まず実口座READ ONLY取得（現在調査中）を動かす。
2. 本物のNo.1.1ライブ判断 → 注文RSS → 約定/現金/枠の連動を実装し、オフラインとPCで動作を確認する。
3. 実注文の送信操作は、完成した発注回路に対してExcel側の**唯一の手動許可ON**を使う。Ark独自の追加許可を要求しない。

## 現在の実装との違い
- 現在のPR #591はDraft/READ ONLY。全executionフラグfalse、`RssStockOrder` は**TEXT ONLY、trigger=0**。今回の文書はこれらを勝手にONへしない。
- 現行の `No11SafetyLedger` には手動承認を要する `explicitSafetyReset` がある。これは今の隔離型検証の暫定実装であり、本番では自動復旧条件へ整理して**第2の手動許可にしない**。
- 現金が今入っていないことを永続の安全条件とはしない。資金は毎回、実口座の現在値で検証する。
- **口座の資金残高は開発着手・READ ONLY監視・オフライン検証の参加条件にしない。** 残高ゼロを含む有効なRSS現物買付可能額は、その数値のまま読み取る。利用者に事前入金や追加の解除・承認を求めずに、native判断／約定突合コードを模擬データで進める。残高・約定・注文を偽造して実口座の安全認証に使わない。
- **資金不足は新規BUY候補への注文単位の自動拒否**であり、ArkのREAD ONLY監視や研究作業全体を止めるものではない。将来の実注文経路では、発注の直前に実際の現物買付可能額と未約定注文の予約分を照合し、不足ならBUYを送信しない。SELL/EXITの安全評価も、保有の真正性と約定を別に確認する。
- **最終的なユーザー手動操作はExcelのRSS注文利用ON/OFFひとつだけ**。UI2の追加「実運用ON」「本番昇格」「復旧承認」など、二重の手動スイッチは導入しない。一方、Frozen戦略、個人保有隔離、発注IDの重複排除、現金／約定／100株／MAX3、RSS観測の鮮度・障害停止は必要な自動条件として外さない。
- **低遅延の優先順位**：不要な人手の確認待ちや固定スリープを増やさず、変わらない原本や設定は事前検証して再利用する。毎回変わる価格・ソース観測時刻・現金・保有・約定・注文中拘束は意思決定時と注文直前に確認する。独立処理は可能な限り並列化し、誤検証や未来参照を招く近道はしない。実行遅延は工程別に測定し、CI待ち中は独立した開発を進める。

- オフライン試験・実機機能試験は製品品質の確認であり、ユーザーの追加「許可スイッチ」ではない。ブロッカーはバグ・未実装として修正する。
- Excel注文許可がONでも、未接続のnative Selector/Entry/EXIT、証券会社データ時刻、注文ID／約定／資金照合が完成したとみなさない。これらは**手動ロック**ではなく未実装・未証明の機能なので、完成前に実注文可能とは宣言しない。すべてが実装・検証できてからExcelの許可だけで運用できる構成にする。


**No.1.1 Research Freeze、旧Workbook、既存実口座、mainは変更しない。**
