# EXIT所有区分の確認と最小補強（2026-11-02）

## 要求

ARKがEXITできるのは、ARK自身の買い注文に紐づく実約定から作られた保有のうち、現在も同じ口座に保有する数量のみ。
手動売却後の二重売り、手動購入の自動採用、手動で同じ銘柄を買い直した後の誤EXITをしない。

## 確認した実装

基準commit: `7ee286122b2eaf7e4f9a96797216786f60e567dc`。

- `no11_broker_execution_ledger.apply_receipt` は、記録済みARK注文、発注開始記録、RSS発注ID、証券注文番号、銘柄、売買、口座が一致する約定だけをARK保有に反映する。
- `prepare_order` のSELLは、同じentryIdのARK保有が必要で、既に予約された未約定売り数量を控除する。
- `no11_broker_execution_service.observe_envelope` は未帰属の保有・手動注文を `broker.externalSymbols` に保存する。外部注文の行が消えても除外を消さない。
- `_sell_safe` は最新の受信スナップショット、外部所有区分、同じ口座の実保有、手動の売り注文を確認する。
- したがって、手動銘柄の非採用、手動売却後のEXIT拒否、同じ銘柄の手動買い直し後の除外保持は既存の基本方針として実装済み。新しい独立所有台帳を重複追加しない。

## 追加した補強

`tools/no11_exit_ownership_patch.py` は上記serviceの既知blobを検証し、次の補強だけを別ファイルへ出力する。

1. SELLの実送信直前、既存の読み取り専用observerファイルを再読込して正規化・照合する。
2. 送信対象が記録済みのARK売り注文であり、同じentryIdのARK残数量以内であることを再確認する。
3. 既存 `_sell_safe` を再実行し、手動売却・手動買い直し・外部売り予約を反映する。
4. 不一致はIN_FLIGHTの確定とtransport呼出しより前に停止する。古い成功記録へのフォールバックや再送はしない。
5. CANCELは保有ゼロでも必要になり得るため、このSELL専用追加ガードで妨げない。既存の取消検証は変更しない。

モデル、EXITシグナル、買い条件、注文数量、口座、SOR、送信許可、資金台帳は変更しない。

## 期待する動作

| 状況 | 動作 |
|---|---|
| ARKが買った100株をそのまま保有 | 通常のEXIT条件と安全確認を満たす場合だけ売却候補 |
| ユーザーがARK購入分を先に全売却 | 実保有ゼロまたは外部売却検知により追加SELL拒否 |
| ユーザーが一部売却 | 元の全数量を再送しない。手動取引が混在した銘柄は保守的に停止 |
| ユーザーが別銘柄を手動購入 | ARK台帳に採用しない。EXIT候補にしない |
| 手動売却後に同じ銘柄を買い直す | 数量が元に戻っても外部除外を消さない |
| ARKと手動の同銘柄保有が混在 | 所有帰属を推測せず、その銘柄の自動SELLを止める |
| RSS不明・古い・照合失敗 | 新たなEXIT送信をしない |

手動売却をARKの約定として偽造しない。現在の対応は安全な売却停止であり、手動売却の利益計上や残株の自動引継ぎを実装したものではない。
既存コードは所有区分衝突時に新規BUYも停止する。この監査・補強はその挙動を緩めない。

## 検証と限界

`tests/test_no11_exit_ownership_patch.py` は実serviceのメソッドをASTで取り出して実行する。模型化するのは正規化済み入力、observer、transport、台帳境界。SQLite除外永続化には実ledgerを使用する。
検証には手動全売却、一部売却、手動購入、同銘柄買い直し、別口座、古いデータ、準備後の手動売却、再起動後の除外保持を含む。

これはExcel実機や実口座での同時操作試験ではない。既に証券会社へ送信済みの注文と、その直後の手動操作を原子的に同期・取り消す機能ではない。観測前に発生した変更や既送信注文の競合を完全に排除したとは主張しない。取引結果が不明な注文は再送しない。

今回ユーザーが手動でExcelから購入した8729も、ARKエンジンの記録済み買い注文でなければ外部保有。勝手に自動売却対象へ追加しない。
